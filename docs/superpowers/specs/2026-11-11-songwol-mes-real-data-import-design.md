# 송월타월 MES 실데이터 DB 로드 및 추천질문 설계

## 1. 목표

2026년 10월 28일 수집된 송월타월 서울상사 MES 엑셀 데이터를 기존 송월타월 AI Agent의 읽기 전용 데이터 허브에 연결한다. 사용자는 수주·미출고·재고·작업지시·공정·생산·포장·KPI 현황을 `송월아` 콜네임으로 질문하고, 좌측 화면의 추천질문 10개를 통해 바로 조회할 수 있어야 한다.

## 3. 데이터 저장 전략

### 3.1 DB 분리

실데이터는 `data/songwol_mes.db`에 저장한다. 기존 `data/songwol_demo.db`는 회귀 테스트와 데모 모드용으로 유지한다.

환경변수 `SONGWOL_DB_PATH`로 사용할 DB를 선택하며, 실데이터 DB를 사용하는 경우 workspace 메타데이터는 다음을 표시한다.

- `demo_data: false`
- `source: 송월타월MES_화면별데이터_20261028.xlsx`
- `as_of: 2026-10-28`
- `approval: 원본 조회 데이터·자동 승인 아님`

### 3.2 재현 가능한 import

엑셀을 매번 수동 편집하지 않고, 서버나 배포 이미지에 원본을 포함하지 않은 상태에서도 지정된 경로에서 import할 수 있는 일회성/반복 실행 스크립트를 추가한다.

- 헤더 행이 시트마다 다른 점을 처리한다.
- `[목록 그리드]`, `[상세 그리드]` 안내 행은 데이터로 적재하지 않는다.
- 빈 시트는 스키마는 만들되 0건으로 기록한다.
- 숫자·날짜·빈값을 안정적으로 변환하고 원본 문자열이 필요한 필드는 보존한다.
- 반복 실행 시 동일한 원본 기준으로 중복되지 않도록 `source_file`, `source_sheet`, `source_row`를 포함한 적재 메타데이터와 upsert 전략을 사용한다.
- import 결과로 시트별 행 수, 제외 행 수, 변환 오류 수를 출력하고 검증 로그를 남긴다.

## 4. 테이블 및 도구 경계

### 4.1 우선 연결할 업무 영역

원본 시트의 의미를 기존 샘플 테이블에 억지로 맞추지 않고 MES 전용 테이블로 분리한다.

- `mes_customers`: 거래처 식별·구분 중심의 비민감 필드
- `mes_items`: 제품구분, 제품코드, 품명·규격, 단위, 적정재고, 용도, 사이즈
- `mes_orders`: 수주번호, 주문일자, 담당자, 거래처, 작업, 품명·색상, 수량, 출고예정일, 배송, 상태 요약
- `mes_shipments`: 수주대비출고, 미출고, 출고현황 데이터
- `mes_inventory`: 품번, 품명·규격, 단위, 이월·입고·출고·현재고·금액
- `mes_work_orders`: 작업지시서 및 생산 작업
- `mes_process_tracking`: 작업지시별 완료·생산완료·포장완료
- `mes_production_results`: 생산번호, 품명·규격, 생산량
- `mes_material_issues`: 자재현장투입 기록
- `mes_packing`: 포장작업 기록
- `mes_kpi`: KPI 지표 및 구축 전후 값
- `mes_source_rows`: 원본 시트·행·정규화 payload를 추적하는 근거 테이블

입고·출고 검사, 불량, 발주, BOM 등은 원본 행이 실제로 존재하는 경우에만 동일한 패턴으로 확장한다. 현재 기본 조회 결과가 0건인 시트는 빈 결과를 미확인 또는 데이터 없음으로 구분한다.

### 4.2 읽기 전용 도구

FastAPI 뒤에 다음과 같은 제한된 조회 도구를 둔다.

- `get_mes_orders`: 미출고·납기·거래처·작업 기준 수주 조회
- `get_mes_inventory`: 현재고·음수재고·재고금액·품목 기준 조회
- `get_mes_work_progress`: 작업지시·생산완료·포장완료 차이 조회
- `get_mes_production`: 기간·수주번호·품명 기준 생산실적 조회
- `get_mes_material_issues`: 수주별 자재현장투입 조회
- `get_mes_shipments`: 수주대비출고·미출고·출고잔량 조회
- `get_mes_customer_summary`: 거래처별 수주량·매출액 집계
- `get_mes_kpi`: KPI 구축 전후·변화량 조회
- `get_mes_source_rows`: 필요한 경우 시트·행 근거 확인

브라우저에는 DB 경로, SQL, 원본 엑셀 경로, provider key를 노출하지 않는다. 임의 SQL·쓰기 도구·출하 승인·재고 수정·작업지시 변경은 추가하지 않는다.

## 5. 추천질문 UI

좌측 질문 패널에 `MES 실데이터` 그룹을 추가하고 기본 선택 그룹으로 둔다. 이 그룹은 정확히 다음 10개 질문을 표시한다.

1. 송월아, 현재 미출고 수주와 수주잔량을 납기순으로 보여줘
2. 송월아, 7일 이내 출고예정인데 아직 미출고인 주문을 알려줘
3. 송월아, 현재고가 음수이거나 재고 확인이 필요한 품목을 알려줘
4. 송월아, 재고금액이 큰 품목과 현재고를 보여줘
5. 송월아, 작업공정별 지시수량·생산완료·포장완료 차이를 알려줘
6. 송월아, 최근 생산실적을 수주번호와 품명별로 집계해줘
7. 송월아, 오늘 생산작업과 포장작업 대상 목록을 알려줘
8. 송월아, 수주별 자재현장투입 내역과 투입수량을 보여줘
9. 송월아, 거래처별 수주량과 매출액 상위 현황을 알려줘
10. 송월아, KPI 구축 전후 지표와 변화량을 요약해줘

각 질문은 실제 도구와 일대일로 연결되어야 하며, 연결되지 않은 질문은 추천질문으로 노출하지 않는다. 답변에는 발견 내용을 먼저 쓰고 `근거:` 뒤에 원본 시트명, 행 식별자 또는 import 기준일을 표시한다.

## 6. 개인정보·민감정보

원본 거래처 데이터에는 주소·전화번호·휴대폰·이메일·사업자번호가 있고, 사용자관리·사용내역관리에는 사용자·권한·접속 IP가 있다.

- AI 추천질문과 기본 조회 도구는 민감 연락처·주소·사업자번호·접속 IP·권한·로그인을 반환하지 않는다.
- 거래처 집계는 거래처명 대신 내부 거래처코드 또는 비민감 표시를 우선한다.
- 원본 파일은 저장소·정적 웹 번들·Docker 이미지에 복사하지 않는다.
- 운영 배포 전 접근코드 이상으로 인증·RBAC·감사정책을 별도 검토한다.

## 7. 오류와 데이터 품질

- 원본 파일 경로가 없으면 서버 시작 시 조용히 샘플로 대체하지 않고 명확한 설정 오류를 표시한다.
- 시트가 없거나 헤더를 판별하지 못하면 해당 시트의 import 오류를 기록하고 전체 결과에 표시한다.
- 숫자·날짜 변환 실패는 0으로 바꾸지 않고 원본값과 오류 상태를 보존한다.
- 값이 없는 상태와 실제 0건을 구분한다.
- 실데이터 답변은 가상 샘플 답변과 다른 배지·메타데이터를 사용한다.

## 8. 검증 계획

1. 원본 시트별 행 수·헤더·제외 행 수 import 검증
2. DB 테이블별 건수와 원본 목록 시트의 건수 대조
3. 수주잔량·현재고·생산완료·포장완료·KPI 합계 샘플 대조
4. 읽기 전용 도구별 API·근거 테스트
5. 10개 추천질문이 실제 도구를 호출하고 근거를 반환하는지 테스트
6. 좌측 패널 기본 그룹과 모바일 패널에서 질문이 표시되는지 확인
7. 기존 데모 DB 회귀 테스트와 프론트엔드 빌드 유지
8. 실제 개인정보가 추천질문 답변과 정적 번들에 포함되지 않는지 확인

## 9. 제외 범위

- PostgreSQL 전환과 AWS 배포
- 실데이터를 저장소에 커밋하거나 공개 정적 자산에 포함하는 작업
