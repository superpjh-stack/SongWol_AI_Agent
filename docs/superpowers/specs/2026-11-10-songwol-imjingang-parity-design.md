# 송월타월 AI Agent 임진강김치형 고도화 설계

## 1. 목표

송월타월 제조 현장의 수주부터 출하까지의 기록을 한 화면에서 확인하고, 임진강김치 AI Agent와 같은 수준의 근거 기반 대화·업무 화면·실시간 음성 경험을 제공한다.

이번 구현의 공식 콜네임은 **“송월아”**로 한다. 사용자가 “송월아”라고 부른 경우에만 음성 응답과 대화 턴을 시작하며, 주변 대화나 비호출 발화에는 응답하지 않는다.

## 2. 현재 상태와 원칙

- 송월타월 V2에는 이미 대화, 현장 현황, LOT, 자료실, 접근코드, 일별 재고·출하, 실시간 음성의 기반이 있다.
- 현재 작업 디렉터리에는 사용자가 진행 중인 미커밋 변경이 있으므로 기존 변경을 초기화하거나 덮어쓰지 않는다.
- 임진강김치의 화면 구조와 상호작용 원칙은 재사용하되, 데이터 모델과 용어는 송월타월 제조 업무에 맞춘다.
- 모든 조회는 읽기 전용이며 자동 출하 승인, 설비 제어, 재고 변경은 범위에서 제외한다.
- 데모 데이터는 실제 운영 데이터와 분리하고, 답변에 샘플·미승인 상태를 명시한다.

## 3. 사용자 경험

### 3.1 기본 화면

상단 업무 내비게이션과 반응형 3영역 구조를 유지한다.

- 대화: 제조 질문, LOT 선택, 데모 조회/AI 분석, 음성 시작·종료
- 현장: 생산·품질·재고·출하 요약과 주의 항목
- LOT: 인쇄 LOT, 작업지시, 품질 결과, 공정조건, 관련 기록
- 자료: 승인 상태가 표시된 기준서·작업서·문서 검색

데스크톱에서는 좌측 자료/질문, 중앙 대화, 우측 현황·추천 질문을 제공하고 모바일에서는 패널을 전환한다.

### 3.2 업무 데이터

송월타월의 업무 흐름은 다음 순서로 연결한다.

`수주 → 작업지시 → 원사/인쇄 LOT → 공정조건 → 품질검사 → 재고 → 출하 → 클레임`

단위와 지표는 다음을 지킨다.

- 생산·재고·출하 수량: EA
- 품질: Delta E, 검사시간, 측정값, 합격·보류 상태
- 식품 제조 용어 및 김치 배합 데이터는 사용하지 않는다.

## 4. 에이전트 동작

### 4.1 데모 조회

질문 키워드에 따라 송월타월 SQLite 샘플의 허용된 읽기 전용 도구를 호출하고, 답변과 함께 원본 레코드 ID 또는 문서 개정번호를 표시한다. 데모 조회는 AI 추론이 아니라 결정적 조회임을 UI에 표시한다.

### 4.2 AI 분석

서버가 관리하는 OpenAI 설정으로 근거 조회 도구를 호출한다. 대화 이력은 참고 데이터로만 전달하고, 도구 조회 결과에 없는 사실은 “미확인”으로 답한다. 오래 걸린 요청은 취소할 수 있고 취소된 응답이 새 질문을 덮어쓰지 않도록 요청 세대와 AbortController를 사용한다.

### 4.3 음성

- 호출명: `송월아`
- 호출명 없는 발화: 텍스트 기록·응답·도구 호출을 만들지 않는다.
- 호출명 뒤의 발화를 하나의 명시적 사용자 턴으로 큐에 넣고 순차 처리한다.
- 도구 호출 중에는 다음 응답을 시작하지 않는다.
- 응답 종료·페이지 이동·LOT 변경·토큰 변경 시 WebRTC, 마이크 트랙, 오디오 객체, 큐를 정리한다.
- 음성 답변도 동일한 근거 조회 도구와 송월타월 범위를 사용한다.

## 5. API 및 근거 경계

기존 V2 API 계약을 우선 보존하고 누락된 경우에만 보완한다.

- `/api/workspace`: 요약, LOT, 질문, 데모 기준일, 음성 설정 상태
- `/api/chat`: 데모/AI 질문, 선택 LOT, 대화 이력
- `/api/tables/{table}`: 허용된 테이블의 읽기 전용 레코드
- `/api/lots/{lot_id}`: LOT 상세 및 연관 근거
- `/api/documents`: 문서 검색
- `/api/daily`: 일별 재고·출하 계획·실적
- `/api/realtime/session`: 음성 세션 발급

접근코드가 필요한 원격 요청은 인증 없이 데이터와 문서를 반환하지 않는다. 로컬 개발 접속 예외와 서버 OpenAI API 키 설정은 기존 정책을 유지한다.

## 6. 오류·안전 처리

- “기록을 불러오지 못했습니다”와 같은 오류는 원인별로 인증 실패, 네트워크 실패, 빈 데이터, 서버 오류를 구분해 표시한다.
- 새로고침 실패 시 기존 화면의 마지막 정상 데이터를 유지하고 재조회 버튼을 제공한다.
- 음성 권한 거부, 안전하지 않은 컨텍스트, WebRTC 오류를 사용자 언어로 표시한다.
- 샘플 데이터는 모든 화면에서 “가상 샘플·미승인”으로 표시한다.
- 제조 기록을 근거 없이 보완하거나 실제 출하를 승인하는 표현을 하지 않는다.

## 7. 검증 계획

구현 후 다음을 순서대로 검증한다.

1. Python API 테스트: 인증, workspace, 문서, 테이블, LOT, 일별 조회, chat
2. 콜네임 테스트: `송월아` 포함 발화만 음성 사용자 턴으로 처리되는지 확인
3. 음성 회귀 테스트: 중복 전사, 도구 호출 직렬화, 취소 후 잔류 응답, 리소스 정리
4. 프론트엔드 빌드와 UI smoke 테스트: 대화·현장·LOT·자료 이동, 접근코드, 새로고침 실패
5. 송월 도메인 회귀 테스트: EA, Delta E, 인쇄 LOT, 출하 기록이 올바른 근거로 표시되는지 확인

## 8. 제외 범위

- AWS 배포와 도메인·인증서 변경
- PostgreSQL 전환
- 설비 제어 또는 출하 승인 자동화
- 실제 승인 문서·운영 DB의 무검증 연결
