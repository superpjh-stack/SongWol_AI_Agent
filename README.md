# 송월타월 서울상사 AI Agent V2

`new-agent-maker` 스킬의 평창꽃순이김치 사례를 활용해 송월타월용 대화·현장·LOT·자료 화면을 구성했습니다. React 19 · TypeScript · Vite 7 + FastAPI 기반이며 기존 송월 SQLite 데이터·읽기 전용 조회 도구와 Streamlit V1(`app.py`)을 유지합니다.

## V2 실행

프로젝트 루트에서 실행합니다. Python 3.12와 Node 22 이상을 사용합니다.

```bash
python3.12 -m venv .venv-v2
.venv-v2/bin/pip install -r v2/requirements.lock
npm ci --prefix v2/web
npm run build --prefix v2/web
.venv-v2/bin/uvicorn v2.api:app --host 127.0.0.1 --port 8513 --no-proxy-headers
```

접속: http://127.0.0.1:8513. 데모 조회는 API 키 없이 동작합니다. 기본 포트 8510은 기존 다른 앱과 충돌하여 송월타월에는 8513을 사용합니다.

개발할 때는 별도 터미널에서 `npm run dev --prefix v2/web`를 실행합니다. Vite는 `/api`를 8513으로 전달합니다.

## 송월타월 MES 실데이터

2026-10-28 수집 MES 원본은 저장소에 복사하지 않고 import 스크립트로 별도 SQLite DB에 적재합니다.

```bash
.venv-v2/bin/python -m v2.mes_import "/원본경로/송월타월MES_화면별데이터_20261028.xlsx" --db data/songwol_mes.db
```

실데이터 모드는 `.env`의 `SONGWOL_DB_PATH=data/songwol_mes.db`로 선택합니다. 현재 로컬 개발 환경은 이 MES DB를 사용하도록 설정되어 있습니다. DB에는 수주·미출고·재고·작업지시·공정 Tracking·생산실적·자재투입·생산작업·포장작업·거래처 집계·KPI를 읽기 전용으로 저장하며, 답변 근거에는 원본 시트명과 행 번호를 표시합니다. 거래처 연락처·주소·사업자번호·접속 IP·권한·사용내역은 AI 조회 payload에서 제외합니다.

## V2 기능

- 상단 **대화·현장·LOT·자료** 메뉴와 해시 경로·브라우저 뒤로가기. 기본 진입은 `/#/assistant`
- 대화 화면: **왼쪽 추천·최근 질문 / 중앙 대화·LOT·음성 / 오른쪽 지식베이스·데이터허브**
- 현장 화면: 진행 주문·품질 보류·재고 주의·출하 승인 대기 집계와 관련 원본 목록 → LOT 상세 또는 현황 질문
- LOT 화면: LOT·주문·상태 검색, 생산수량(EA), 작업지시·수주·품질·공정·재고·출하·클레임 원본 → 선택 LOT로 질문
- 자료 전체 화면: 문서 검색·본문과 11개 허용 테이블 탐색, 조회 실패 재시도 및 빈 결과 구분
- 지식베이스 샘플 문서 10종 · 검색·본문 / 데이터허브 8개 테이블 각각 10개 연결 레코드
- 중앙 대화·인쇄 LOT 선택·데모/AI 전환·새 대화·실시간 음성
- 추천질의: 실데이터 모드 `MES 실데이터` 10개, 샘플 모드 기존 20개 · 왼쪽 세션 질문 이력 최대 20개
- 모바일 자료·질문 패널, 키보드로 닫을 수 있는 문서·설정 대화상자
- 직접 입력·추천질문·이력 재질문의 동일한 처리 경로
- 문서 개정번호·미승인 상태와 실제 호출된 도구의 원본 결과·출처·조회시각 표시
- LOT 전환·새 대화·모드 변경 시 요청 취소 및 이전 응답 무시
- LOT 추적에 완제품뿐 아니라 작업지시에 연결된 원단 재고 포함

현장 집계는 전체 DB 기준이고 목록은 기존 API가 반환하는 첫 10개 레코드에서 해당 조건을 필터링합니다. 화면에 조회 범위를 표시합니다. 출하 기록은 주문 기준 연결이며 특정 LOT의 출하 수량을 확정하는 자료가 아닙니다. 같은 LOT에서 메뉴를 이동하면 문자 대화는 유지하고, 음성은 화면을 떠날 때 연결과 마이크를 해제합니다. LOT 변경 시 대화를 초기화하며 선택한 데모/AI 모드는 유지합니다.

데모는 규칙에 따른 키워드 검색입니다. AI 요약·원인 분석을 수행하지 않습니다. V2의 문서는 `sample_docs/*.md`를 직접 읽으며 클라우드 업로드 없이 조회합니다. 샘플 모드에서는 기존 제조 도구와 일별 조회 도구를 사용하고, MES 모드에서는 `get_mes_*` 읽기 전용 도구로 원본 시트·행을 조회합니다. PostgreSQL·외부 ERP 직접 연결은 하지 않습니다.

샘플 기준일은 **2026-09-03**입니다. 수량의 원본 단위는 **EA**이며 품질 값은 ΔE, 흡수시간 초, 강도 N으로 표시합니다. 샘플 문서는 실제 승인 문서가 아니므로 기존의 `상태: 승인` 표시를 미승인 샘플로 수정했습니다. 실제 품질 기준이나 공정 최적화 수치를 만들지 않습니다.

기준일 **2026-10-09**, 과거 15일과 미래 15일을 포함해 **2026-09-24~2026-10-24 총 31일**을 등록합니다. 모든 행은 `source=demo_data`이며 단위는 EA입니다.

| `shipment_actuals` | 32 | 9월 24일~10월 9일 하루 2건, 완전·부분 출하 샘플 |

09:00 기준 독립 재고 스냅샷이며 출하량을 다시 차감하는 재고 원장이 아닙니다. 미래 출하실적은 만들지 않습니다. 계획·실적은 품목과 고객을 연결한 별도 물류 샘플이며 기존 9월 LOT별 출하 배분은 미확인입니다. 기존 주문·LOT·품질 DB와 문서를 덮어쓰지 않습니다.

- 대화 왼쪽 **재고·출하** 추천질문: 오늘 재고, 안전재고 미달, 출하계획·실적·미출하, 내일 계획·예상재고, 앞으로 15일 계획, 지난 15일 실적, 전체 기간 재고 추이
- 현장 화면 아래 **일별 재고·출하**에서 날짜 선택 → 해당 날짜 질문
- 자료 → 데이터허브의 새 일별 테이블 3개는 선택 날짜의 전체 레코드를 표시
- 문자 AI·음성은 동일한 읽기 전용 `get_daily_operations` 도구를 사용
- `오늘/내일/어제`는 한국시간 서버 날짜 기준. 앞으로 15일은 내일부터, 지난 15일은 어제까지이며 오늘을 중복 포함하지 않음
- 고정 구간 밖 날짜는 자료 없음으로 응답. 재시작 날짜에 맞춰 과거를 이동하거나 예상치를 실적으로 바꾸지 않음
- `INSERT OR IGNORE`로 재실행 시 기존 행과 수정값을 보존

예: `2026-10-09 재고현황`, `2026-10-24 출하계획`, `지난 15일 출하실적`, `내일 예상 재고`.

## AI와 음성 설정

로컬 앱의 설정 또는 마이크 버튼에서 **OpenAI API 키 → 저장하고 음성 시작**을 선택합니다. 키와 음성 모델 접근을 확인한 뒤 서버 `.env`에 소유자만 읽고 쓸 수 있는 권한으로 저장하고 즉시 적용합니다. 키는 브라우저 저장소나 응답에 넣지 않으며, 입력란도 처리 후 비웁니다. 브라우저 마이크 권한을 허용하면 음성 질문과 답변을 시작합니다. 다음 접속부터는 마이크 버튼으로 바로 시작할 수 있습니다. 키 설정 경로는 직접 로컬 접속과 동일 출처에서만 사용 가능합니다.

직접 설정하려면 `v2/.env.example`을 참고해 필요한 값을 루트 `.env`에 설정합니다. API 키는 서버에만 저장하며 `VITE_*`에 넣지 않습니다.

- `OPENAI_API_KEY`: 서버의 OpenAI 키
- `OPENAI_MODEL`: 기존 기본값 `gpt-5.6`, 계정에서 사용 가능한 모델로 설정
- `OPENAI_REALTIME_MODEL`: 스킬 기본값 `gpt-realtime-2.1`
- `OPENAI_REALTIME_VOICE`: 기본값 `marin`
- `COCKPIT_ACCESS_TOKEN`: 처음 한 번 입력하는 접근 코드. 서버가 확인한 코드는 이 브라우저의 localStorage에 저장해 탭·브라우저를 다시 열어도 재사용합니다. 기존 sessionStorage 코드는 첫 정상 접속 시 자동 이전합니다. 설정에서 저장된 코드를 지울 수 있으며, 서버 코드 변경·브라우저 저장소 삭제·다른 브라우저 이용 시에는 다시 입력합니다. API 키와 다릅니다.
- `SONGWOL_DB_PATH`: 기본 `data/songwol_demo.db`; 실데이터 모드는 `data/songwol_mes.db`로 설정

이 컴퓨터의 `http://127.0.0.1:8513` 또는 `http://localhost:8513`로 직접 접속하면 서버 접근 코드 설정 여부와 관계없이 입력 화면 없이 바로 시작합니다. 클라이언트 주소와 요청 호스트가 모두 로컬이어야 하며 전달된 프록시 주소가 있으면 이 자동 연결을 적용하지 않습니다. 외부에서는 문서·레코드 조회를 포함한 모든 업무 API에 코드를 요구합니다. 이 코드는 개인 계정·역할 권한 기능이 아닙니다. 외부 운영 배포 시 HTTPS, 사용자 인증·RBAC 및 실데이터 출처 정리가 별도로 필요합니다.

실시간 음성은 WebRTC, 한국어 자막, 발화 종료 감지, 끼어들기, 음소거·종료, LOT 전환 시 자원 해제를 구현했습니다. 서버 도구 핸들러와 실제 SQLite 어댑터를 연결하고 음성 조회 근거도 화면에 표시합니다. 마이크는 HTTPS 또는 localhost에서 사용합니다. 음성과 문자 대화는 각각 별도 AI 문맥이며 선택 LOT를 공유합니다.

API 형식 참고: [OpenAI 공식 WebRTC 가이드](https://developers.openai.com/api/docs/guides/voice-webrtc), [Realtime 대화 이벤트](https://developers.openai.com/api/docs/guides/realtime-conversations). 모델 접근 권한과 실제 음성 품질은 별도로 확인해야 합니다.

송월타월 서울상사의 **문서 지식**과 **MES형 제조 데이터**를 함께 검색하는 실행형 Streamlit 프로토타입입니다. 색차 예측이나 공정 최적화 모델은 제외하고 RAG 질의응답에만 집중했습니다.

## Agent Cockpit 화면

- 상단 KPI, 대화이력·추천질문, 중앙 RAG 채팅, 선택 인쇄 LOT의 품질·출하·클레임 및 승인대기를 한 화면에 배치했습니다.
- 추천질문, 과거 질문 재실행, 선택 LOT 브리핑은 동일한 채팅 라우트로 처리합니다.
- RAG-only 범위를 유지하며 색차 예측·공정 최적화·Vision AI·자동 제어/승인은 추가하지 않았습니다.

## RAG 범위

- 비정형 지식: 작업표준서(SOP), 품질 기준서, 상품설명서, 클레임·유지보수 매뉴얼
- 정형 지식: 수주, 작업지시, 원단/인쇄 LOT, 생산실적, 품질, 재고, 출하, 품목 기준정보
- 제조 조회: 주문 현황, LOT 정·역추적, 품질 보류, 안전재고, 출하 승인, 클레임 조회
- 근거 표시: 검색 문서명, 문서 검색 결과, 호출한 제조 Data Hub 도구
- 운영 통제: 읽기 전용 도구, 사람 승인, 최소권한, 감사로그, 문서 버전 관리 원칙

화면의 주문·LOT·수치·고객명은 검증용 가상 데이터입니다. 약 200종 품목과 재고 약 8억원, 구글시트·수기 중심 운영, MES+AI Agent 구축 방향은 제공된 기준정보를 반영했습니다.

## 실행

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
streamlit run app.py
```

`.env`에 `OPENAI_API_KEY`를 설정해야 RAG 채팅과 문서 인덱싱을 사용할 수 있습니다. API 키 없이도 제조 데이터 미리보기는 가능합니다.

## 데모 절차

1. 앱을 실행하고 OpenAI API 키를 입력합니다.
2. `지식문서` 탭에서 `sample_docs/` 파일을 업로드합니다.
3. RAG Agent에서 아래 질문을 시험합니다.

```text
PRT-260903-C LOT가 왜 보류됐고 출하에 어떤 영향이 있어?
SO-260901의 생산·품질·출하 상태를 요약해줘.
안전재고 미달 품목을 알려줘.
색상 클레임 처리절차를 문서 근거와 함께 알려줘.
```

## 운영 전 교체·확인

- SQLite 데모 저장소를 MES/ERP/WMS/QMS 읽기 전용 API 또는 조회 View로 교체
- 주문·작업지시·원단 LOT·인쇄 LOT·품목·출하 키의 일관성 검증
- 문서별 소유자·개정번호·승인상태·시행일·폐기상태 메타데이터 적용
- 부서별 RBAC와 고객·단가·클레임 민감정보 마스킹
- 대표질문 평가셋으로 근거정확성, 답변충실도, 미답변, 권한위반 검증
- 질문·검색문서·도구호출·응답 감사로그 및 백업·복구 절차 적용

### 송월 호출 규칙

에이전트 콜네임은 **송월아**입니다. 문자와 음성 모두 매 질문을 `송월아, 오늘 재고 알려줘`처럼 시작합니다. 이름 없는 질문이나 `송월`, `송월님`으로 시작하는 질문에는 답하지 않습니다. 추천질문에도 `송월아`가 포함됩니다.

문자 입력은 브라우저와 API에서 AI 호출 전에 검사합니다. 음성은 Realtime 자동 응답을 끄고 최종 한국어 전사 결과에서 `송월아` 호출명을 확인한 뒤에만 응답을 요청합니다. 미호출 발화는 대화에서 제거하며 호출된 질문만 순서대로 처리합니다. 마이크 연결 중에는 호출명 인식을 위해 음성이 서버로 전송되므로, 로컬 오프라인 호출어 감지는 아닙니다. 음성 인식이 이름을 다르게 받아쓰면 답하지 않을 수 있습니다.
