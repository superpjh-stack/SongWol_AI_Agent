# 송월타월 V3

make_best2_agent를 기존 송월타월 MES 앱에 병합했다. 기존 DB, 인증, 음성, 복합질문, 자료/LOT 화면과 답변 시작 위치 유지 동작을 보존한다.

## 화면과 API

- 연구소: 타월 품질 탐정, 상품 아이디어 공방, 한 장의 여정, 업무 브리핑. `POST /api/studio`의 LangGraph collect → draft → verify 흐름으로 사실·원인 후보·창작을 나누고 근거 ID를 검사한다. 검사 통과는 제조 안전성 인증이 아니다.
- 기존 AI 설정이 있으면 공방의 AI 생성 선택 가능. 기본 모드는 기획 템플릿이다. 실패를 성공으로 숨기지 않는다.
- `POST /api/reports`의 kind는 `daily-production`, `production-summary`, `inventory`. 대화 요청과 왼쪽 보고서 리스트, 보고서 화면이 같은 생성 함수를 사용한다.
- `GET /api/reports/{id}/xlsx|pdf`: 생성 당시 JSON 스냅샷을 내려받는다. Excel은 기본 양식 + 원본 스냅샷 시트, PDF는 반복 머리말과 페이지 번호가 있는 인쇄 문서다. 특정 고객의 승인 양식을 복제한 것은 아니다.
- 원본 MES 생산실적 7,166행은 전체를 읽어 품목 573개로 묶는다. 단위·일자·양품/불량 구분이 없는 값을 추정하지 않는다. 생산번호에서 날짜를 추정하지 않는다.
- 일일생산보고서는 샘플 work_orders의 종료일 기준으로만 생성 가능하다. 현 MES에는 생산일자가 없어 안내 오류를 반환한다. 실제 일일보고서 도입에는 생산일자, 품목 코드, 수량 단위, 계획/양품/불량 매핑이 필요하다.
- 재고는 원본 스냅샷이며 임의 날짜 필터 불가. 재고의 서로 다른 단위를 합산하지 않는다. LOT 필터와 지원하지 않는 기간 필터는 거절한다.
- 생산·재고 원본은 변경하지 않는다. 새 저장 테이블은 `v3_report_exports`뿐이다. 기존 회사 단위 접근 코드 인증을 그대로 적용한다. 개별 사용자 계정 체계가 없어 개인별 문서 소유권을 제공한다고 주장하지 않는다.
- 보고서는 서버에 보관된다. 실제 운영에서 저장 기간·삭제 정책은 별도 결정할 수 있다.

## 검증

`.venv-v2/bin/python -m pytest v2/tests tests -q`와 `npm run build --prefix v2/web`.

로컬 MES DB의 SQLite backup 사본으로 PC/390px 모바일 연구소, 보고서 생성, 대화 요청, Excel/PDF 다운로드를 검증했다. 운영 배포와 실제 마이크/외부 AI 호출 검증은 이번 작업에 포함하지 않는다.
